# Edge-AI path B: GD32H759 (recommended second-source MCU)

Runtime: code generated by **GigaDevice GD32 Embedded AI** (tested version to record: v1.3.0.x).
Backend: `ai/backends/ai_backend_gd32.c`. Shared logic: `ai/ai_health.c` (same on both paths).

Why the GD32H759: Cortex-M7 at 600 MHz, 1 MB SRAM, up to 3.75 MB flash, 3 CAN FD controllers.
Same core as the STM32H743, so the int8 model, the CMSIS-NN-class kernels and the PAL split carry over.

## PoC phase 1: inputs ready in `tools/edge_ai_poc/phase1_artifacts/`

| File | Use in the tool |
|---|---|
| `cnn/model.h5` or `cnn/saved_model/` | model to import (deployment candidate) |
| `cnn/model_fp32.tflite`, `cnn/model_int8.tflite` | alternative import formats |
| `lstm/model.h5`, `lstm/saved_model/` | second candidate (better F1, 4.4x the compute); let the tool quantise it |
| `calib.npz` | quantisation calibration: key `x` float32 (320, 60, 9), normalised; key `y` int64 labels |
| `test.npz` | evaluation: key `x` float32 (574, 60, 9), normalised; key `y` labels |
| `scaler.json` | the normalisation the firmware applies before inference (`ai/generated/ai_scaler.h`) |
| `report.json` | host reference results to compare against |

VERIFY on first use: the key names the tool expects inside an NPZ. If it wants other names
(for example `input` or `input_1`), re-save with
`np.savez('calib_tool.npz', input_1=np.load('calib.npz')['x'])`.

## Steps on the Windows PC

1. Open GD32 Embedded AI, new project, target **GD32H759**, import `cnn/model.h5`.
2. Quantisation: int8 PTQ, calibration file `calib.npz`.
3. Validate on host with `test.npz`. Record accuracy and the tool's int8 vs float agreement.
   Pass: macro-F1 >= 0.90 for the model alone (`report.json`: 0.908 int8).
4. Repeat steps 1 to 3 with `lstm/model.h5`. Phase 1 could not int8-convert the LSTM with TensorFlow
   2.21 (converter crash), so this is the first int8 LSTM result. Keep it if F1 stays near 0.947
   and the latency fits.
5. Generate the Keil or IAR project. On a GD32H759 board, run the tool's benchmark: latency, flash,
   RAM. Pass: < 2 ms per inference, < 64 KB flash, < 32 KB RAM.
6. Replace the two placeholder externs in `ai/backends/ai_backend_gd32.c` with the generated API.
   If the generated network takes int8, quantise in `gd32_infer()` with the scale and zero point
   the tool reports.
7. Build: copy the generated model sources to a folder and pass
   `-DAI_BACKEND=gd32 -DGD32AI_DIR=<folder>` (GD32 PAL port and BSP required for the full image).
   Check that the generated code builds with arm-none-eabi-gcc; if it needs Keil-only libraries,
   record that as a portability finding.
8. Fill in the table below and compare with path A.
