Graphics framework strategy for the maximatecc maxAI roadmap

Where embedded HMI graphics is heading across agriculture, construction, forestry, mining, material handling and specialty vehicles, and what that means for maximatecc display hardware and firmware. Built from public sources, a jobs-to-be-done analysis and a structured debate between cross-functional expert panels.

EVIDENCE stated in a cited public source JUDGMENT panel assessment, not measured VERIFY check before it drives a decision

Bottom line

The framework war is ending in coexistence, and AI coding tools are making the framework itself less of a moat. Customers will keep choosing between Qt, CODESYS and LVGL, with MCU-vendor tools and Slint at the edges. What they will pay for is what surrounds the framework: machine signals ready to bind, safety-certified rendering, fast simulators, update and cyber compliance, and an AI-ready toolchain that turns a design or a spec into tested HMI firmware.

Recommendation: position maxAI as a framework-neutral HMI platform. That means one signal layer, one safety island, one build, simulation and over-the-air pipeline, and three supported runtimes (Qt 6, LVGL 9, CODESYS Visualization), with an agent interface that lets Claude Code and similar tools build on it safely. Use tiered hardware so the same software stack runs from an MCU smart display up to a multi-screen cockpit computer.

Is Claude Code changing embedded graphics?

Yes, early and unevenly. The signals are real, but most are anecdotal.

  • EVIDENCE The LVGL community has published an agent skill that lets Claude Code or Cursor generate SquareLine Studio projects as LVGL widget trees, with a validator. Engineers report feeding wireframes to AI tools for the first draft of a UI.
  • EVIDENCE Vendors are adapting to agents. Qt Design Studio's assistant is now agentic over MCP and turns Figma selections into QML. LVGL's editor exposes code generation, Figma sync, validation and tests through a CLI.
  • EVIDENCE Practitioners say AI-written LVGL code works but must be reviewed for memory use, and that general assistants can invent hardware register details.
  • JUDGMENT The effect is a shift in where value sits. When an agent writes screens in hours, nobody pays for familiarity with a framework's API. Value moves to four things agents cannot invent: correct machine signals (CAN/J1939 databases bound to widgets), a fast simulator and tests that catch what the agent got wrong, safety and cyber evidence, and clear licensing.
  • JUDGMENT Text-based UI formats (QML, LVGL XML, .slint) gain; binary or proprietary project files lose. Per-device royalties come under more pressure, because they become the largest remaining cost of an HMI.

The same pattern already shows in this repository. The AI Terra mower HMI firmware was written with Claude Code behind a GUI bridge with interchangeable TouchGFX and Qt for MCUs backends, plus 1,458 host tests. That is the kind of agent-built, framework-neutral, test-gated work maxAI should make routine.

Design-thinking framing

Empathize

  • Ride-alongs with operators across 3 industries: in-cab video, glove and glare tests.
  • Shadow OEM HMI and controls teams through one variant release.
  • Interview dealers about the last 10 field failures.

Define

  • Point of view: OEMs do not buy a framework; they buy time to a validated screen on a certified machine.
  • The deciding owner is often the controls team, not the HMI team.

Ideate (how might we)

  • …make the first screen appear on real hardware on day one?
  • …let CODESYS, Qt and LVGL teams share one signal model?
  • …certify telltales without certifying the GUI framework?
  • …let an AI agent build screens without breaking safety or memory budgets?

Prototype and test

  • A "48-hour HMI" kit: DBC file + Figma frame + agent skill → running screen on a CCpilot unit, scored by OEM engineers.
  • A/B test a cockpit layout with operators, measuring task time and errors.
  • A safety-island demo with deliberately corrupted GUI output.

Expert panel debate

Six cross-functional panels argued the question from their own discipline. Each card gives the panel's position, the pros and cons it weighed, and the strongest dissent raised against it.

Cockpit and vehicle architecture

Machine architects, zonal E/E, 48 V systems

Machines are moving to zonal layouts with central compute. Excavators already carry up to four displays; consolidation onto fewer, smarter displays or one cockpit computer is coming.

ProFewer boxes; one UX across screens; lower harness cost.
ConMixed-criticality software on one SoC needs a hypervisor and safety partitioning.

Dissent: mid-size OEMs will keep separate displays for a decade, so the ECU-by-ECU market stays large.

Graphics and HMI frameworks

Qt, LVGL, CODESYS and Slint specialists

No single winner. Qt keeps premium Linux HMIs, LVGL takes MCU and cost-down designs, CODESYS keeps PLC-centric OEMs. Supporting only one framework loses deals.

ProA multi-runtime platform matches how customers actually buy.
ConThree runtimes triple validation and support effort.

Dissent: pick LVGL as the strategic default and treat Qt as a premium add-on, to escape royalty pressure.

Functional safety and compliance

ISO 25119, ISO 13849, IEC 61508, cyber

Nobody will certify a full GUI framework. Put safety-relevant rendering on an independent island with output checks. The EU Machinery Regulation (applies January 2027) and the Cyber Resilience Act make SBOMs and secure updates mandatory.

ProOne safety concept works under every framework.
ConExtra hardware cost and a longer certification lead time.

Dissent: Qt Safe Renderer already covers this; building our own island duplicates it. VERIFY regulation dates.

Silicon and hardware platform

SoC/MCU selection, thermal, supply chain

Offer three tiers on one SDK: an MCU smart display, a Linux display with an NPU for edge AI, and a cockpit computer with GPU and safety domain. Keep two silicon sources per tier where possible.

ProCovers $150 to $3,000 price points with shared software.
ConMCU vendors push their own free GUI tools, which pulls customers into single-vendor lock-in.

Dissent: an MCU tier competes with cheap commodity displays where maximatecc has little edge.

Business, licensing and channel

Pricing, partner programmes, procurement

Royalty-bearing runtimes are becoming the largest visible HMI cost. Bundle licenses into the hardware price, and charge for platform services instead: SDK support, OTA and fleet services, safety evidence packs.

ProRecurring revenue; procurement sees one price.
ConMargin pressure if Qt royalties are absorbed into the hardware price.

Dissent: Qt partner status still opens doors at large OEMs; don't be seen as moving away from Qt.

AI tooling and developer experience

Agentic coding, CI, simulation

Design the SDK for agents first: text UI formats, a machine-readable signal model, a desktop simulator, a CLI, screenshot tests and an MCP server for the device. Humans benefit from the same things.

ProDays-to-first-screen becomes a sellable metric.
ConGenerated code needs review against memory, timing and safety budgets; liability questions.

Dissent: OEM IT policies may block cloud AI tools, so local or on-premise models must also work.

Panel debate

"Go high-end"

Cockpit architecture panel

The full software-defined cockpit, and the money in it, sits with large OEMs. A cockpit computer with a safety domain is the only way to avoid becoming commodity glass.

Counter: large OEMs insource the software (Deere G5 is the template). What's left for a supplier is ODM hardware at large-OEM purchasing margins, against Tier-1s such as Bosch, Continental and Danfoss with far bigger engineering teams.

"Own the mid-to-high band"

Business, licensing and channel panel

Mid-size and upper-mid OEMs want the same features as large OEMs (OTA, multiple displays, telematics, AI assist) but cannot build the platform. They pay for a finished base. Here an SDK is the product.

Counter: mid-size OEMs are cautious buyers, and volumes per design-in are modest, so sales cost per unit is high.

"Don't ignore the long tail"

AI tooling and developer-experience panel

AI agents let small OEMs get custom screens without an HMI team. A CODESYS-ready display, a template library and agent skills could reach hundreds of small OEMs through distributors.

Counter: CODESYS-first competitors (ifm, Intercontrol, OpenView, TTControl) already price for this tier. Only enter if the channel does the selling.

"Watch China and the fast followers"

Silicon and hardware panel

Fast-growing Chinese OEMs (XCMG ranks third globally) adopt software-defined cockpits fast and source locally. Their displays reset price expectations everywhere.

Counter: Western mid-size OEMs facing EU cyber and machinery rules may prefer a European supplier with compliance evidence.

Verdict on where to play

  • Primary: mid-to-high. Upper-mid OEMs and the second tier of large OEMs (global ranks roughly 10–50). Sell maxAI as an "SDV-lite" platform: one to three displays, OTA, telematics, safety island, multi-framework SDK.
  • Selective: high end. Bid for large-OEM programmes as hardware, BSP and safety-island partner where the OEM brings its own software. Do not build a full cockpit computer until Scenario 5 signposts move.
  • Through channel: low end. A CODESYS-ready display with templates and agent-built screens, sold by distributors. No custom engineering.

Before this drives investment, test it with a sized model: count OEMs by tier and segment, estimate display units per year, and score which tiers are open to an outside platform. Start from KHL Yellow Table data for construction and equivalent rankings for agriculture and material handling.

SWOT: maximatecc SDK strategy

The SWOT covers the recommended framework-neutral maxAI SDK. A comparison of the four SDK strategies maximatecc could pick follows it, then the strategies that combine the SWOT quadrants.

Strengths

  • Installed CCpilot base with Qt and CODESYS already supported
  • Data Engine already bridges CODESYS and Qt: the seed of one signal layer
  • Rugged off-highway hardware know-how and long product lifecycles
  • i.MX 8 platform family from 7" to 12" shares one software base

Weaknesses

  • Small software organisation compared with Qt Group, CODESYS or large Tier-1s
  • Three runtimes multiply validation, support and documentation
  • No published safety-island or certified rendering offer yet
  • Unclear public brand: maximatecc, CrossControl and Scanreco VERIFY
  • Thin cloud, telematics and AI tooling today

Opportunities

  • Qt 5 end of support forces every Qt 5 customer to re-decide
  • Mid-size OEMs want SDV-lite features without building a platform
  • AI-agent workflows reward text UI formats, simulators and signal models, which an SDK can provide
  • EU Machinery Regulation and CRA create demand for compliance as a service
  • LVGL partner programmes and NPUs on newer i.MX parts enable new tiers and edge-AI features

Threats

  • Large OEMs insource cockpit software (the Deere G5 model)
  • MCU vendors give away GUI tools tied to their own chips
  • CODESYS-first display competitors: ifm, Intercontrol, Helios OpenView, TTControl
  • Qt moving deeper into tooling and MCUs; could bypass display makers
  • Lower-cost Asian displays; AI lowering barriers for new entrants
  • Liability for defects in AI-generated HMI code
